# Background

When there's IRS booked by Blade/Stella, all the fix leg cashflow would be generated as the rate are known. These fix leg interest payment will be available in Ratan in advance probably in 'PROJECTED' status. The corresponding floating leg payment will be generate when the floating rate is fixed which normally happen on VD-2. As the Settlement practice client would expect SCB to settle the net amount of the fix leg & floating leg for each schedule.

# Cashflow Logic (Source from Murex 2.11)

### For CN/SG/IN/MY (All In Real Time)

- VD-7, Fixed leg (C1) is sent to RATAN with pending_fixing flag as Y.

MXML Path: /MxPayML/scbExtraInfoBlock/isWaitingFixing

Physical [Model:/scb:SCBML/scb:payload/scb:cashflowPayload/scb:cashflow/scb:pendingFixingFlag](http://Model/scb:SCBML/scb:payload/scb:cashflowPayload/scb:cashflow/scb:isPendingFixing)

Logical Model: Cashflow.Pending_Fixing_flag

- Once C1 is materialized, keep C1 as WAITING + Pending another leg status
- On VD-1/VD-2, Fixing is done on the Floating leg (C2)
- MX2.11 will send the reversal of Fixed leg (C1) and send the net amount to RATAN (C3)
- RATAN would cancel C1, and process C3 as a normal cashflow
- Note: In case of dispute, the underlying component cashflow details have to be looked at in MX2.11

### For UK/DE (In Batch)

- For VD-2 to VD-7, Fixed leg (C1) is sent to RATAN with pending_fixing flag as Y.

MXML Path: /MxPayML/scbExtraInfoBlock/isWaitingFixing

Physical [Model:/scb:SCBML/scb:payload/scb:cashflowPayload/scb:cashflow/scb:pendingFixingFlag](http://Model/scb:SCBML/scb:payload/scb:cashflowPayload/scb:cashflow/scb:isPendingFixing)

Logical Model: Cashflow.Pending_Fixing_flag

- Once C1 is materialized, keep C1 as WAITING + Pending another leg status
- Later, Fixing is done on the Floating leg (C2) - If MX2.11 send the reversal of Fixed leg (C1) and send the net amount to RATAN (C3) in real time with flag X. - RATAN would cancel C1 without pending another leg - RATAN would process C3 blocked with NSTP Rule 'Fixing Unknown' - Then Murex would send a file "FMRP_MUREX_FIX_FLAG" with actual pending fixing flag N for C1 reversal and C3 ```xml FLOW_ID;WAIT_FIX 110777819;N 110777820;N 110777821;N 110777823;N 110777824;N 110777826;N 110777985;N 110777986;N 110777987;N 110777988;N 110777995;N 110777997;N 110778423;N 110778426;N 110778442;N 110778443;N 110778444;N 110778446;N 110810074;N 110810075;N ``` - File process condition: Cashflow Status == WAITING & Sub Status type== Pending Exception & Sub Status in(Pending Operator, Pending Verification) & Exception code == 'Fixing Unknown' - RATAN wouldn't process C1 reversal as C1 is cancelled already. - RATAN would process C3 for rest checking for STP - If MX2.11 send the reversal of Fixed leg (C1) and send the net amount to RATAN (C3) in batch with flag N - RATAN would cancel C1 without pending another leg - RATAN would process C3 for rest checking for STP

### For UK/DE (In Real Time)

- For VD to VD-1, Fixed leg (C1) is sent to RATAN with pending_fixing flag as X.

MXML Path: /MxPayML/scbExtraInfoBlock/isWaitingFixing

Physical [Model:/scb:SCBML/scb:payload/scb:cashflowPayload/scb:cashflow/scb:pendingFixingFlag](http://Model/scb:SCBML/scb:payload/scb:cashflowPayload/scb:cashflow/scb:isPendingFixing)

Logical Model: Cashflow.Pending_Fixing_flag

- Once C1 is materialized, Payment will be blocked with NSTP Rule 'Fixing Unknown'
- Then Murex would send a file "FMRP_MUREX_FIX_FLAG" with actual pending fixing flag Y/N - If cashflow flag is Y, then cashflow should be in WAITING + Pending another leg status - If cashflow flag is N, then go through rest checking for STP
- Later, Fixing is done on the Floating leg (C2)
- MX2.11 will send the reversal of Fixed leg (C1) and send the net amount to RATAN (C3) in real time with flag X. - RATAN would cancel C1 without pending another leg - RATAN would process C3 blocked with NSTP Rule 'Fixing Unknown'
- Then Murex would send a file "FMRP_MUREX_FIX_FLAG" with actual pending fixing flag N for C1 reversal and C3 - File process condition: Cashflow Status == WAITING & Sub Status type== Pending Exception & Sub Status in(Pending Operator, Pending Verification) & Exception code == 'Fixing Unknown' - RATAN wouldn't process C1 reversal as C1 is cancelled already. - RATAN would process C3 for rest checking for STP

# Logic to Identify IRS Interest cashflows

- applicable for **Stella **cashflows

if (CashFlowInfo.Data_Flow__Data_Source_System=='Stella' and Instrument_Common.ISDA_Taxonomy in(' InterestRate:IRSwap:FixedFloat','InterestRate:IRSwap:OIS','InterestRate:IRSwap:FloatFloat','InterestRate:IRSwap:FixedFixed') and Cashflow.Payment_Type in('**Coupon/Fixed**','**Coupon/Float**') )  and Cashflow.Cashflow_Event_Type  != Withdrawal

Then compare cashflow number with TDX for same cashflow ID and value date,

If RATAN cashflow number < TDX cashflow number, then update status to "WAITING + Pending another leg"

else go to next check

- applicable for **Murex **cashflows

if  (CashFlowInfo.Data_Flow__Data_Source_System=='Murex' and pending_fixing flag='Y' and Cashflow.Cashflow_Event_Type != Withdrawal

If pending_fixing flag='Y', then update status to "WAITING + Pending another leg"

else go to next check
