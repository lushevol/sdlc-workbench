Cashflow hold in the pending auto netting status which not be processed because of the rule changes need to be manually checked by OPS 1. For example: if the cashflow hit netting rule, but the rule was deleted or updated before netting datetime which cause the cashflow will not be auto netted by system, the cashflow will still be hold in pending auto netting, OPS need to manually process the cashflow
2. if there are multiple rules created, system will perform netting inside of each rule, no cross rule netting | rule1 | - counterparty A - Product A | | --- | --- | | rule2 | - booking entity A - counterparty A - ccy A - Product B | | Cashflow for product A <u>will </u>**<u>not</u> **net with cashflow for product B |
3. default priority is based on netting time user set, if the time is set to the same, take system created time. - if cashflow meet multiple rule. The earlier job will trigger the netting and rest will be ignored | rule1 | - VD-1 18:00 | | --- | --- | | rule2 | - VD 16:00 | | rule3 | - VD 18:00 | | if cashflow match above 3 rules, it will be netted by the rule 1 since the date time is earlier |
4. Auto netting rule check should happen after manual netting rule check, before multiple exception check.
5. Cashflow hit the auto netting condition will be hold in the "pending auto netting" queue until the user defined netting date time
6. action to be enabled for "Pending auto netting" , 1. settle as gross (add a warning ) - bulk allowed? 2. net selected cashflow (add a warning to indicate the cashflow is for auto netting) 3. other actions (suppress, failed, hold... are disabled the same as pending netting status)
7. "net selected cashflow" is allowed between these status: pending netting, pending auto netting, pending exception
8. if there is only one cashflow hit the rule until netting date time, netting job will release the cashflow from pending auto netting queue to multi-exception check, should trigger an exception "Single Cashflow"
9. Cashflow received after netting date time will not be hold for auto netting?- send to manual netting queue. ~~*"Past auto netting time"?*~~ | Event Date | Payment Date | Netting Date Time | Expected Result | | --- | --- | --- | --- | | 20240717 20:00 | 20240718 | VD-1 18:00 | not hold for auto netting, **pending netting** status waiting user manual action |
10. netting resultant cashflow will be hold NSTP
11. manual/system un-net cashflow will skip auto netting rule check and be hold in NSTP
12. trade affirm/confirm component cashflow will not impact cashflow, align with pending netting behavior
