# Auto Netting Summary

> **Auto Netting Summary**
>
> ## Data Source
>
>
> This section defines the data sources used by Auto Netting only. It covers auto rule retrieval, auto configuration, and auto queue cashflow lookup.
>
>
> | **Source Type** | **Table** | **Query / Filter** | **Usage** |
> | --- | --- | --- | --- |
> | Auto netting rules | ratanone_rule_service.ratan_rule_engine | rule_type = 'AUTO_NETTING' | Retrieve auto netting rule set |
> | Auto netting type configuration | cash_netting_service.ratan_auto_netting_type_config | By active configuration and netting type | Resolve auto netting grouping and execution configuration |
> | Auto netting cashflow queue | cash_settlement_query_cn.cashflow_data | WAITING | Query auto netting cashflows and support auto flow actions |
>
>
> ## Process Overview
>
> This section describes the end-to-end process from eligible rule matching, queueing, and schedule trigger to grouping and resultant cashflow creation, including the main configuration used at each step.
>
> | **Step** | **Description** | **Main Configuration Used** |
> | --- | --- | --- |
> | 1. Eligible check | Incoming cashflow is evaluated against LIVE auto netting eligible rules. | ratanone_rule_service.ratan_rule_engine |
> | 2. Queue for auto netting | If the cashflow matches a rule, it is stored in DB and waits until the configured schedule time. | user_rule and meta_data.autoNettingConfig |
> | 3. Schedule trigger | At the configured schedule time, the auto netting job picks up queued cashflows for execution. | Netting Date, Netting Time, STP Setting |
> | 4. Grouping for netting | Cashflows are grouped by the configured netting key for that Netting Type. | cash_netting_service.ratan_auto_netting_type_config.net_group_key_config |
> | 5. Actual netting | Only cashflows with exactly the same netting key values can be netted together. | Netting type execution key |
> | 6. Resultant creation | A resultant cashflow is created based on the configured resultant mapping. | resultant_mapping_config |
>
> ## Key Business Point
>
> > **NOTE**
> > Matching an eligible rule does not automatically mean cashflows will net together.
> >
> > Cashflows that match the same eligible rule will only be netted together if all values in the configured execution key for that Netting Type are identical.

# Manual Netting Summary

> **Manual Netting Summary**
>
> ## Data Source
>
>
> This section defines the data sources used by Manual Netting only. It covers manual rule retrieval and manual queue cashflow lookup.
>
>
> | **Source Type** | **Table** | **Query / Filter** | **Usage** |
> | --- | --- | --- | --- |
> | Manual netting rules | ratanone_rule_service.ratan_rule_engine | rule_type = 'NETTING' | Retrieve manual netting rule set |
> | Manual netting cashflow queue | cash_settlement_query_cn.cashflow_data | WAITING | Query manual netting cashflows and support user actions |
> | Manual rule source file (documentation reference) | ratan_rule_engine_manual_netting.csv | N/A | Input source for Manual Netting Rules rendering |
>
>
> ## Process Overview
>
>
> Manual netting follows an operator-driven path after cashflow entry. The flow performs **Eligibility Check**; eligible records are parked in **Pending Netting** queue, where the user executes **Net** or **Cancel Net**.
>
>
> If **Net** is selected, the process creates a **Resultant Cashflow** and publishes it back to the netting flow. If **Cancel Net** is selected, the process routes back to **Netting Flow** for re-entry and re-processing.
>
>
> ## Key Business Point
>
> There are 3 netting types allowed to manual netting: CCIL Net Selected Cashflow, BIC Net Selected Cashflow, Net Selected Cashflow.
>
> | **Manual Netting Action** | **Eligibility Conditions** | **Eligible Execution Netting Key** |
> | --- | --- | --- |
> | CCIL Netting | Counterparty SCI FMID <> 400021949 and Counterparty SIC BIC Net Flag <> Y and Settlement Method = "CCIL" and Splitting Id is empty and Settlement_Method <> "UTIL". | Same(Entity__Booking_Entity_SCI_FMID + Entity__Counterparty_SCI_FMID + Cashflow.Cashflow_Payment_Date)+Settlement_Method == "CCIL"+Entity__Counterparty_SCI_BIC_Net_Flag == "N" |

> | Bilateral Netting | Counterparty SCI FMID = 400021949 and Counterparty SIC BIC Net Flag <> Y and Settlement Method = "CCIL" and Splitting Id is empty and Settlement_Method <> "UTIL". | Same(Entity__Booking_Entity_SCI_FMID + Entity__Counterparty_SCI_FMID + Cashflow.Cashflow_Payment_Date + Cashflow.Cashflow_Payment_Date)+Entity__Counterparty_SCI_BIC_Net_Flag == "N" |

>
> Manual netting is state-aware and action-driven: only records in **WAITING + Pending Netting** should be presented for user decision.

>
