## 2. SAFE change checklist

| Key Checks | Description | Is the change compliant with "SAFE" criteria - YES/NO/NA <Comment is mandatory for No/NA> |
| --- | --- | --- |
| **No deletions / Amendments ** | **Implies** : Change that does not delete or amend existing database/data/systems **Target** : Immutable infrastructure and non-destructive rollouts | No - EG RTGS payment still generates MT and fix address length limitation for unstructured address |
| **Backward compatibility** | **Implies** : Change should be backward compatible to ensure that newer systems, software, or devices can seamlessly work with older versions or legacy data **Target** : Upgrade won't "break" existing tools, seamless upgrades, phased migrations, preventing sudden disruptions | Yes |
| **Automated System restarts ** | **Implies **: Were its relevant system restarts are fully automated (application shuts down and boots back ) with minimal manual intervention for faster uptimes **Target** : Routine Maintenance, Systems updates , crash recovery etc. where a device, server, or software application shuts down and boots back up entirely on its own. | Yes |
| **Automated Change Rollback** | **Implies** : As part of rollback plan a change should encompass automated change rollback to it’s a previous stable state with minimal manual intervention **Target** : Robust pre-deployment practices, database backward compatibility, documented runbooks, rigorous testing to support automated rollback | Yes |
| **Rigorous Testing** **(within the remit of the change and its dependencies)** | **Implies **: Validating new code, infrastructure, or configurations in a safe, isolated/lower/non-prod/pre-pod environment to prevents bugs, security vulnerabilities, and system outages in production **Target **: Testing systems through phased environments, automated testing, and defined operational readiness gates to ensure successful deployment | Yes |
| **Change Impact assessment (CIA)** **(within the remit of the change and its dependencies)** | **Implies** : Change impact assessment in terms of how the deployment will have a cascading impact to the technical infrastructures, business operations and client journeys - both positive and negative—of deploying new software, hardware, or system updates **Target **: Review dependency mapping, tested rollout and backout plans, updated runbooks and supportability to evaluate the technical, operational, and user-facing effects of a deployment | Yes |
| **Automated deployment** | **Implies** : Using ADO for automated pipeline deployment or in certain cases using tools and scripts to automatically push software, hardware, or system updates from development into production, minimizing manual deployments **Target : **Shift from manual to automated workflows that allow support to deploy changes safely and autonomously by automating the change lifecycle, risk-based routing, automated testing and validation | Yes |
| **Eliminate/Minimize Outage** | **Implies **: Deployment through a structured implementation plan to prevent, minimize, or eliminate system downtime **Target :** Comprehensive risk assessment, dependency mapping, pre-testing ,blue-green deployment or use canary release by leveraging automation and observability to reduce or eliminate downtime | Yes |
| **Change Risk assessment (CRA)** **(within the remit of the change and its dependencies)** | **Implies **: Change assessment to identify, analyze, and mitigate potential risks/hazards before implementing a change **Target :** Define the scope, identify potential impact, analyze potential threats to operations, evaluate the likelihood and impact, and establish robust mitigation and rollback plans | Yes |
| **Change Dependencies** | **Implies **: Change scope mapping of which software, hardware, upstream and downstream applications and journeys are within the scope of deployment and impact **Target **: integrate mapping directly into your CI/CD pipelines, adopt CMDB mapping to ensure right scoping and impact radius | Yes |
| **Change deployment timelines are been coordinated** **(Cross domain Muti-support deployment)** | **Implies : **Aligning the technical rollouts with support staff and synchronizing system updates, to ensure smooth deployment **Target :** Aligning technical milestones with cross-functional readiness through a centralized review framework, automated deployment pipelines and structured communication | Yes |
| **Change Communication** | **Implies :** Pre/During/Post communication - transparently explaining the why (benefits), the what (about) and How (progress of deployment) **Target **: Phased communication plan, communicating pre-planning, timelines, outcome and during deployment milestone progress updates | Yes |
