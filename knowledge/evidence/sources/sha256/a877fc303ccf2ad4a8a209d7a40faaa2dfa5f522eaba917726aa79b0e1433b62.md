# Background

The change is raised in scope of settlement day2. User expects to be able to set up auto netting rules from UI for system to net the cashflow which met the rules automatically. This will result in 1 hour saving per day.

**NOT** refresh cashflow in WAITING (Pending Another leg, Pending Auto netting) READY (Pending Ack), HOLD, SUPPRESSED, NETTED, RELEASED, SETTLED - if data ops **disable existing auto netting rule, **system will refresh below cashflow - **NOT** refresh cashflow in WAITING (Pending Another leg, Pending Auto netting) READY (Pending Ack), HOLD, SUPPRESSED, NETTED, RELEASED, SETTLED - Update manual netting rule to auto netting rule - **Refresh **Netting id ='' or Netting id is null** **and Cashflow_Status = WAITING (Pending Netting, Pending Exception) or Cashflow_Status = READY (cashflow state type is null) and meet the rule condition - 3. Cross rule netting is <u>**not**</u> allowed, system will perform net with **netting key + unique identifier for the rule **such as bilateral netting, system will net cashflow with same** (***booking_entity+counterparty+ccy+VD)* + Rule_ID(or some other unique identifier of the rule)** ** - sample**: ** | | Rule 1 | Rule 2 | | --- | --- | --- | | Rules | - booking entity A - counterparty A - Product A - netting date: VD-1 - MAKER_ONLY - Bilateral Netting | - booking entity A - counterparty A - Product B - netting date: VD-1 - MAKER_ONLY - Bilateral Netting | | Group Result | cashflow hit rule 1 will not be net with cashflow hit rule 2 |
4. Single Cashflow: cashflow hit auto netting rule, but there is no other cashflow to net with, scheduled job will release the cashflow from auto netting queue after netting date time and apply the same STP level configured in the netting rule. The cashflow **should <u>NOT</u>** be tagged as settleAsGross, if user reinstate the cashflow, it will hit the auto netting rule again.
5. if cashflow hit more than one auto netting rule, 1. the system checks netting-type priority and assigns the rule with the highest priority (that is, the lowest configured number) to the cash flow 2. If the matched rules have the same netting type, the system selects the rule that was created later.
6. Auto netting (with affirmation) should be captured in the audit history, action ='Net' user = "System"
7. Actions allowed for pending auto netting : same as pending netting , please refer to the page for details [[User Actions on Cashflow Blotter]]
8. Actions allowed for netting resultant cashflow are the same between manual netting resultant and auto netting resultant
9. Net over net is not supported, but need to support auto net over IRS netting resultant.
