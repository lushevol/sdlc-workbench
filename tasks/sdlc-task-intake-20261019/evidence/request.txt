The first step of the SDLC is receiving a requirement or an issue.

First, create a folder named tasks directory at root, specifically for that requirement or issue. Then, use templates to flesh it out and apply drilling with stock to clarify it. You must have a clear and confident understanding of the requirement or issue before moving to the next step.

Data comes from two main sources:

1. The knowledge directory, which contains the project's domain knowledge.
2. The reports directory, which contains the project's codebase and test cases.
3.Investigation results.

You cannot proceed until you fully understand the requirement or issue. You can also gather additional data through other sources:

1. Run an end-to-end investigation using a real browser or Playwright for UI validation to check if the issue exists, determine the current state of the requirement, and inspect the pre-implementation state.
2. If it is a service or business requirement, verify the live data flow or system behavior in the production system.
3. Check existing test cases in the test engine to infer system behavior.

Continue gathering evidence and information until you have enough to support moving to the next step, and save all that evidence under the same task.
